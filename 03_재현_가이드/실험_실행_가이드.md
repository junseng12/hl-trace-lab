# Hyperliquid 이중 장부·체결 상대방 추적 실행 가이드

이 프로젝트는 (1) HyperCore↔HyperEVM 자산 이동과 (2) 오더북 체결 상대방을 공개 자료로 복원합니다.

```text
01_자산이동_8경로/   보고서 2장: 전체 자산 이동 8경로
02_오더북_가치이전/  보고서 3장: userFills + trades WebSocket + node fill archive
```

## 포함 범위

- Mainnet/Testnet HYPE Core↔EVM 공개 추적: 개인키 불필요
- Mainnet 오더북 공개 추적: 개인키 불필요, UI 정상 거래만 수동 수행
- Testnet/Mainnet 공개자료 수집: 개인키 없이 브라우저 수동 거래를 관찰
- Testnet T1: 통제된 단건 체결
- Testnet T2: 하나의 테이커 주문이 두 메이커에게 분할 체결
- Testnet T3: 하나의 메이커 주문을 두 테이커가 분할 체결
- 과거 체결 보존성 재조회
- 사전 점검과 오프라인 단위 테스트

Mainnet 자동 주문 코드는 포함하지 않습니다. Mainnet에서는 공개 수집기를 먼저 실행하고 사용자가 UI에서 정상적인 소액 거래를 체결합니다.

## 보안 원칙

- `.env.local`은 Git에 포함되지 않습니다.
- `.env.example`에는 공개 가능한 빈 칸만 있습니다.
- `02_오더북_가치이전/실행도구/공개자료_수집.py`는 개인키를 읽지 않고 주문도 전송하지 않습니다.
- Agent 개인키가 필요한 자동 T1/T2/T3은 Testnet API URL만 허용합니다.
- 실행 결과를 저장하기 전에 개인키 문자열 포함 여부를 검사합니다.

## 2. HyperCore ↔ HyperEVM 공개 추적

Core→EVM은 Core의 HYPE `send`와 protocol System TX를 결합합니다. 두 hash는 다르므로 같은 주소·HYPE·정확한 수량·인접 시각을 사용합니다.

```bash
python 01_자산이동_8경로/route04_core_to_hyperevm.py \
  --network mainnet \
  --user 0xTARGET_ADDRESS \
  --start-time-ms 1791884600000 \
  --end-time-ms 1791884720000 \
  --amount 0.005 \
  --output 결과/core_to_evm.json
```

EVM→Core은 사용자가 HYPE System Address로 보낸 표준 EVM TX hash에서 시작합니다.

```bash
python 01_자산이동_8경로/route05_hyperevm_to_core.py \
  --network mainnet \
  --evm-tx-hash 0xEVM_TRANSACTION_HASH \
  --output 결과/evm_to_core.json
```

결과가 `UNIQUE_MATCH`일 때만 자동 확정합니다. `AMBIGUOUS_OR_NOT_FOUND`이면 시간창을 줄이거나 추가 근거를 확보합니다. 1~8번 전체 명령은 [`01_자산이동_8경로/README.md`](../01_자산이동_8경로/README.md)를 보십시오.

## 3. 공개 수집기 — Testnet

```bash
source .venv/bin/activate
```

`READY`가 표시되면 브라우저에서 정상 소액 거래 1건을 체결하고 터미널에서 Enter를 누릅니다.

## 4. 오더북 공개 수집기 — Mainnet

```bash
source .venv/bin/activate
STAMP="$(date +%Y%m%d_%H%M%S)"
OUT="결과/수동_메인넷_$STAMP"

python 02_오더북_가치이전/mainnet_live_trace.py \
  --user "0xMASTER_ADDRESS" \
  --market "HYPE/USDC" \
  --output-dir "$OUT" \
  --crosscheck-counterparties
```

Mainnet에서는 자신의 다른 지갑 주문과 맞추지 않고 공개 오더북에서 정상적인 소액 거래만 수행합니다.

주소나 시장을 여러 개 감시하려면 `--user`, `--market`을 반복합니다. `userFills`의 신규 체결과 WebSocket의 공개 체결을 `(coin,time,tid)`로 결합합니다.

결과 구조:

```text
00_manifest.json       실행 조건
01_pre_accounts.json   거래 전 userFills
02_pre_markets.json    거래 전 recentTrades·호가
03_ws_trades.ndjson    실시간 시장 전체 체결
04_post_accounts.json  거래 후 userFills
05_post_markets.json   거래 후 recentTrades·호가
06_summary.json        상대방 결합 결과
```

## 5. 자동 Testnet T1/T2/T3

```bash
cp .env.example .env.local
chmod 600 .env.local
```

`.env.local`에 Testnet의 네 Master 공개 주소, 승인된 Agent 주소, Agent 개인키를 입력합니다. Master 개인키와 시드 문구는 입력하지 않습니다.

사전 점검:

```bash
python 02_오더북_가치이전/실행도구/테스트넷_사전점검.py --env .env.local
```

`.env.local`의 `HL_ENABLE_SIGNED_ACTIONS=false`는 변경하지 마세요. 각 Testnet 실행기가 네트워크·주소·Agent 키·안전 한도를 검증한 뒤, 해당 프로세스의 메모리에서만 서명을 일시 허용합니다.

자산 준비:

- T1: W2에 약 10.5 USDC 가치의 HYPE, W1에 USDC
- T2: W1·W3에 각각 약 10.2 USDC 가치의 TEEYI, W2에 USDC
- T3: W1에 약 11 USDC 가치의 TEEYI, W2·W4에 각각 USDC

필요한 HYPE·TEEYI는 Testnet UI에서 미리 소액 매수합니다. 스크립트는 준비된 재고가 부족하면 주문을 거부합니다.

T1 단건 체결:

```bash
python 02_오더북_가치이전/실행도구/테스트넷_T1_단건체결.py \
  --env .env.local \
  --output-dir 결과/T1_단건체결 \
  --execute-testnet-pilot
```

T2 테이커 분할:

```bash
python 02_오더북_가치이전/실행도구/테스트넷_T2_T3_분할체결.py \
  --env .env.local \
  --phase t2 \
  --output 결과/T2_테이커_분할.json \
  --execute-testnet-split
```

T3 메이커 분할:

```bash
python 02_오더북_가치이전/실행도구/테스트넷_T2_T3_분할체결.py \
  --env .env.local \
  --phase t3 \
  --output 결과/T3_메이커_분할.json \
  --execute-testnet-split
```

실행 후 다시 점검:

```bash
python 02_오더북_가치이전/실행도구/테스트넷_사전점검.py --env .env.local
```

열린 주문 0, 예상하지 않은 Perp 포지션 0, Agent→Master 관계 정상을 확인합니다.

## 6. 체결 정보 보존성 재조회

T1/T2/T3에서 생성된 결과를 기준으로 직후·1시간·1일·7일 후 같은 `tid`가 각 공개 데이터 소스에 남아 있는지 비교합니다.

```bash
python 02_오더북_가치이전/실행도구/체결정보_보존성_재조회.py --help
```

실시간 자료를 미리 저장하지 못했고 REST 최근 한도를 벗어났다면 공식 `node_fills_by_block` 시간 파일을 내려받아 로컬에서 결합합니다.

```bash
python 02_오더북_가치이전/node_archive_join.py \
  --input node_data/20260918_09.jsonl \
  --user 0xTARGET_ADDRESS \
  --output 결과/node_counterparties.json
```

다운로드·압축 해제 방법은 [`02_오더북_가치이전/README.md`](../02_오더북_가치이전/README.md)를 보십시오.

## 7. 핵심 판정 로직

```text
userFills(A)에서 신규 (time, coin, tid) 확보
→ WebSocket 또는 recentTrades에서 같은 키 검색
→ users=[buyer, seller]에서 상대방 B 복원
→ B의 userFills에도 같은 키가 있으면 후보 관계 교차검증
```

주문 `oid` 하나가 여러 체결 `tid`와 여러 상대방으로 분리될 수 있으므로 관계 그래프는 `tid` 단위로 생성합니다.

## 8. GitHub 비공개 저장소 운영

팀원은 각자 `.env.local`을 만듭니다. 개인키 파일을 메신저·메일·Git으로 공유하지 않습니다. `git status`에서 `.env.local`, `.venv`, `결과/`의 실행 산출물이 포함되지 않았는지 확인한 뒤 push합니다.
